# virtfs

For new providers, start with the [VFS v2 provider SDK guide](../../../../docs/VFS_V2_PROVIDER_SDK_RU.md).
The public SDK builds on `virtfs` and adds typed resources, collections, documents,
commands and development tools. Ordinary filesystem providers can use the SDK's
backend adapters or keep implementing `FSProvider` directly.

`virtfs` is a small helper for VFS v2 providers that synthesize their own tree.

Use it when a provider is more like Linux `procfs` or `sysfs`: paths look like
files and directories, but the content is generated by Go handlers instead of
coming from an external filesystem.

It helps avoid the boring, easy-to-forget parts:

- `Stat` for every visible path.
- `ReadDir` for directories.
- `OpenFile` for files.
- read-only errors for write attempts.
- default `Mkdir`, `Move`, and `Delete` as `os.ErrPermission`.
- default `Control` as `vfs.ErrNotImplemented`.

## Basic Shape

A `virtfs.FS` implements `vfs.FSProvider`, so a provider can embed or delegate
to it:

```go
type Provider struct {
	fs *virtfs.FS
}

func NewProvider() *Provider {
	return &Provider{fs: buildFS()}
}

func (p *Provider) Stat(ctx context.Context, path string) (*vfs.Node, error) {
	return p.fs.Stat(ctx, path)
}

func (p *Provider) ReadDir(ctx context.Context, path string) ([]*vfs.Node, error) {
	return p.fs.ReadDir(ctx, path)
}

func (p *Provider) OpenFile(ctx context.Context, path string, flags int) (vfs.File, error) {
	return p.fs.OpenFile(ctx, path, flags)
}
```

Or you can return the `*virtfs.FS` directly when that is enough.

## Operations

`virtfs` is read-only by default, but selected routes can opt in to writes.

That default is intentional. Synthetic providers are often used for
introspection, and WebDAV/file-manager clients may create temporary files,
hidden files, or folders without the user thinking much about it. Nothing should
become mutable unless the provider explicitly says so.

Supported opt-in hooks:

- `Mkdir` on the parent directory route.
- `CreateFile` on the parent directory route for `OpenFile(..., O_CREATE)`.
- `Delete` on the existing node route.
- `Move` on the existing source node route.
- `OpenFile` on a file route for custom read/write behavior.

If a hook is missing, `virtfs` returns `os.ErrPermission` for mutating
operations.

Creating a directory is handled by the parent directory:

```go
fs.Route("/projects", virtfs.Handler{
	Stat: func(ctx context.Context, req virtfs.Request) (*vfs.Node, error) {
		return virtfs.DirNode("projects"), nil
	},
	ReadDir: listProjects,
	Mkdir: func(ctx context.Context, req virtfs.Request, name string) (*vfs.Node, error) {
		return createProject(ctx, name)
	},
})
```

Creating a file through `O_CREATE` is also handled by the parent directory:

```go
fs.Route("/configs", virtfs.Handler{
	Stat: func(ctx context.Context, req virtfs.Request) (*vfs.Node, error) {
		return virtfs.DirNode("configs"), nil
	},
	ReadDir: listConfigs,
	CreateFile: func(ctx context.Context, req virtfs.Request, name string, flags int) (vfs.File, error) {
		return virtfs.NewBufferedWriteFile(name, func(data []byte) error {
			return saveConfig(ctx, name, data)
		}), nil
	},
})
```

## Directories

Directories return ordinary `*vfs.Node` entries. Those entries should correspond
to routes that can later answer `Stat`, `ReadDir`, or `OpenFile`.

```go
fs := virtfs.New().
	Dir("/", func(ctx context.Context, req virtfs.Request) ([]*vfs.Node, error) {
		return []*vfs.Node{
			virtfs.DirNode("scopes"),
			virtfs.FileNode("health.txt", 0),
		}, nil
	}).
	Dir("/scopes", func(ctx context.Context, req virtfs.Request) ([]*vfs.Node, error) {
		return listScopeNodes(ctx)
	})
```

## Generated Files

Generated files are read-only files. Their bytes are produced when the file is
opened. `Stat` calls the same generator so the size stays consistent.

```go
fs.GeneratedFile("/health.txt", func(ctx context.Context, req virtfs.Request) ([]byte, error) {
	return []byte("ok\n"), nil
})
```

For JSON, keep JSON outside the core:

```go
fs.GeneratedFile("/scopes/{scopeKey}/info.json", func(ctx context.Context, req virtfs.Request) ([]byte, error) {
	scopeKey := req.Match.Param("scopeKey")
	info, err := loadScopeInfo(ctx, scopeKey)
	if err != nil {
		return nil, err
	}
	return json.MarshalIndent(info, "", "  ")
})
```

## Command-Like Files

Some synthetic files are closer to devices: you write bytes to them and the
provider performs an action when the file is closed.

```go
fs.BufferedWriteFile("/reload", func(ctx context.Context, req virtfs.Request, data []byte) error {
	return reloadWithPayload(ctx, data)
})
```

Reading this file returns `os.ErrPermission`; writing to it accumulates bytes
and calls the handler on `Close`.

The buffered handle also implements `vfs.WriteFile`. Use
`vfs.FinishWrite(file, transferErr)` when copying an input stream: it calls `Abort`
after a transfer error and commits only a complete upload. Repeated `Close` calls
do not repeat the callback and preserve a failed commit's error.

## Control

`Control` is still first-class. Use it when the operation is not naturally a
file read or write.

```go
fs.Route("/connections/{name}", virtfs.Handler{
	Stat: func(ctx context.Context, req virtfs.Request) (*vfs.Node, error) {
		return virtfs.DirNode(req.Match.Param("name")), nil
	},
	Control: func(ctx context.Context, req virtfs.Request, command string, input []byte) ([]byte, error) {
		switch command {
		case "test":
			return testConnection(ctx, req.Match.Param("name"))
		default:
			return nil, vfs.ErrNotImplemented
		}
	},
})
```

## Dynamic Routes

Routes use the same path syntax as `pathmap`:

- `/scopes`
- `/scopes/{scopeKey}`
- `/providers/{providerKey}/info.json`
- `/files/*`

The extracted parameters are available through `req.Match.Param("name")`.

## Mental Model

`virtfs` is not trying to be a real mutable in-memory filesystem. It is a router
for synthetic VFS nodes.
