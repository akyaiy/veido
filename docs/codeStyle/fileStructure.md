# Стилистика структуры проекта

Правила организации структуры модулей, компонентов и файлов проекта.



## Названия модулей

- Использовать понятные и короткие названия.
- Название должно описывать назначение модуля.
- Использовать `camelCase` для названий.
- Избегать непонятных сокращений и не делать названия длиннее 3 слов.
- Не использовать в названиях пробелы, специальные символы и национальные буквы.



## Структура модуля

Модуль - отдельный независимый компонент проекта, содержащий HTML/Markdown-разметку, стили и JavaScript-логику.

- Каждый модуль размещать в собственной папке.
- Каждый модуль должен содержать файлы `content.md`, `script.js` и `style.css`.
- Использовать правила названий из раздела [Названия модулей](#названия-модулей).

Пример:

```text
editorBlock/
├── content.md
├── script.js
└── style.css
```


## Подмодули

- Подмодули размещать в папке `module`.
- Для подмодулей использовать правила раздела [Структура модуля](#структура-модуля).
- Модули должны быть независимыми как от своих вложенных подмодулей, так и от модулей того же уровня вложенности.
- Подмодули могут обращаться к родительскому модулю.

Пример:

```text
editorBlock/
├── content.md
├── script.js
├── style.css
└── module/
    ├── propertiesPanel/
    │   ├── content.md
    │   ├── script.js
    │   ├── style.css
    │   └── module/
    │       └── colorPicker/
    │           ├── content.md
    │           ├── script.js
    │           └── style.css
    └── loadedBlock/
        ├── content.md
        ├── script.js
        └── style.css
```
