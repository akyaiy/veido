# Стилистика Markdown

Правила оформления Markdown кода проекта - структура, форматирование и использование разметки.



## Пробелы и отступы

- Использовать (табуляцию) отступы в 4 пробела.
- Между элементами одного раздела можно оставлять одну пустую строку, а между разными разделами - 3 пустые строки.



## Заголовки

- `#` - основное название документа.
- `##` - заголовки основных разделов.
- `###` - заголовки подразделов и отдельных пунктов.



## Списки

- Использовать `-` для создания списков (не использовать `*`).
- Между символом списка и текстом должен быть один пробел.

Пример:

```md
Название

- Первый пункт.
- Второй пункт.
```



## Ссылки и изображения

- Не использовать прямые ссылки без описания назначения.
- Пути к локальным файлам оформлять через относительные пути.

Пример:

```md
[Документация API](./api.md)
![Схема архитектуры](./img/architecture.png)
```



## Inline-код

Технические элементы оформляются через обратные кавычки.

Используется для:

- имён файлов,
- папок,
- функций,
- классов,
- переменных,
- команд,
- CSS-классов.

Пример:

```md
Используется функция `CanUserAccess()` из файла `acl.go`.
```



## Блоки кода

- Каждый блок кода должен иметь указание языка.
- Код должен сохранять форматирование и структуру исходного файла.

Пример:

```go
func main() {
    fmt.Println("Hello")
}
```



## HTML внутри Markdown

HTML разрешён, когда возможностей Markdown недостаточно.

Используется для:

- сложных структур,
- сеток,
- пользовательских блоков,
- элементов с атрибутами,
- управления отображением.

Пример:

```html
<div>
    <span data-test="test">текст</span>
</div>
```
