# Архитектурные решения

В этой папке находятся самостоятельные ADR проекта. Концепции, обзоры текущей
реализации и планы разработки остаются на уровень выше в `docs/`.

Для ADR-007 актуальное уточнение: scope сайта входит в immutable template
package как `/_static/site-context.json` и выдаётся обычным `get-static`; route
`/_site/context` удалён.

| ADR | Решение | Статус решения | Статус реализации | Примечание |
| --- | --- | --- | --- | --- |
| [ADR-003](ACL_LIFECYCLE_ARCHITECTURE_RU.md) | ACL lifecycle, durable journal, generation, tombstone и overlay | Принято | Не реализовано | В VFSv2 есть только синхронная точка расширения `ResourceLifecycleSink`; journal, generation, tombstone, overlay и recovery отсутствуют |
| [ADR-004](VFS_V2_SHARED_PROVIDER_DECISION_RU.md) | Shared Provider как заменяемая проекция канонических VFS URI | Принято | В процессе | Реализован ACL-free каркас: модель ссылки, собственное SQLite-хранилище без связи с `users`, CRUD записей, `incoming/outgoing`, делегирование через `BoundVFS` и provider-owned migration group; системный database registry не знает Shared, provider не включён в основную pre-prod сборку, `Control` намеренно возвращает unsupported, не реализованы `acl_grant_uri`, ACL и lifecycle |
| [ADR-005](VFS_V2_SCOPE_RESOLUTION_DECISION_RU.md) | Разделение разрешения scope и авторизации входа в него | Принято | В процессе | Explicit/default lookup разделены; VFS Core проверяет synthetic scope gate, traverse `x` предков и action target. `cmd/server` использует ACLv2 и поэтому до bootstrap rules fail-closed; demo-композиции по-прежнему используют временные authorizer-ы. Cross-scope grants отсутствуют |
| [ADR-006](ACL_SPARSE_NAMESPACE_TREE_PROPOSAL_RU.md) | Разреженное дерево ACL namespace, priority 1–100 и управление rule | В процессе | Реализованы SQLite schema, sparse-tree store, trusted Auth group lookup, evaluator, ACL Provider, protected bootstrap grants и подключение в `cmd/server`; lifecycle ещё отсутствует | Заменяет в ADR-003 плоское URI-хранение и prefix overlay для move внутри root: `node_id` остаётся внутренним ключом ACL. Правило выбирается по максимальному priority, deny сильнее только при равенстве. ACL Provider управляет rules; автор active rule — его manager, а control-plane защищён bootstrap root |
| [ADR-007](VFS_V2_HTML_PROVIDER_DECISION_RU.md) | HTML Provider как метадоменная проекция физических файлов сайта | Предложено | В процессе | Реализованы Store schema v5 с миграциями bundle/visibility/templates/blocks, доменное ядро страниц, typed VFS-проекция, обязательная visibility текущих Site/Publisher/Page/Block, безопасный page/block bundle binding и demo `cmd/vfsv2html`; Site HTTP выдаёт scope-only `/_site/context`, не меняет HTML и не передаёт `bundle_root_uri` через bootstrap; browser читает URI bundle только из Page/Block metadata. Editor slice предоставляет actor-filtered `editor/model.xml` и optimistic `editor/layout.xml`; template slice предоставляет атомарную immutable-установку, content-addressed blobs, manifest allowlist и read-only `/templates/<key>/<version>`; reviewed builder собирает `default-spa/11` и устанавливает его через VFS в demo bootstrap. Block slice реализует lazy frontend-библиотеку `ui-component`/`content`, versioned provider-owned `blocks/tree.json` и `/blocks/<key>/meta.json`, без обязательной Page→Block composition; ACL и publication в него не входят. Также отсутствуют active publication, Theme/Publication consumers, поиск/sitemap, production-регистрация, реальный ACL и lifecycle; актуален [практический план](../VFS_V2_HTML_PROVIDER_IMPLEMENTATION_PLAN_RU.md) |
| [ADR-008](VFS_V2_SERVER_HOOKS_DECISION_RU.md) | Серверные hooks как versioned orchestration-сценарии над actor-bound VFS | Предложено | В процессе | Реализованы transport-neutral typed SDK, immutable versioned definitions, trusted native engine, provider-module registration и actor-bound Runtime с limits/structured errors и in-memory idempotency результатов. Hook не прикреплён к resource URI: сценарий получает typed input и выполняет нужные VFS-вызовы тем же actor; HTTP adapter реализует `POST /api/v2/vfs/hooks/{hook-key}/run` только для прямого запуска. Ещё отсутствуют durable execution/step journal, resume/compensation, sandboxed engine, hook policy и observability |
| [ADR-009](PREPROD_SERVER_RUNTIME_DECISION_RU.md) | Единственная pre-prod сборка `cmd/server`, границы runtime и pre-ACL policy | Принято | В процессе | `cmd/server` использует `internal/serverapp` и `.env`/environment config; подключены health, VFS HTTP, Auth hooks и Site HTTP для отдельного `SITE_URI` scope; public-site pre-ACL bridge временно заменяет будущие ACL grants |
| [ADR-010](SQLITE_MIGRATIONS_DECISION_RU.md) | Централизованные ordered/transactional SQLite migrations по группам владельцев | Принято | Реализовано | Общий runner и version table; database registry содержит только core/Auth/VFS, а composition root передаёт выбранные Local/HTML groups; Shared остаётся полностью provider-owned; настроены SQLite open и отдельная `cmd/migrate`, legacy Auth stores сохранены до следующей итерации |
| [ADR-011](AUTH_SESSION_JWT_LIFECYCLE_DECISION_RU.md) | Session-backed JWT lifecycle, разделение access/refresh и fail-closed rotation | Принято | Реализовано | Auth получает secret/issuer/audience/TTL через dependency; runtime использует hashed refresh в `sessions`, CAS rotation и reuse revoke; блокировка, password change и logout отзывают sessions; legacy stores сохранены, но не участвуют в runtime |
| [ADR-012](USERS_PROVIDER_AUTH_HOOKS_DECISION_RU.md) | Guest actor, Users Provider и Auth-owned hooks через единый VFS transport | Принято | Частично устарело | Реализованы session-scoped guest actor, общий scope `system`, Users profile store/provider, Auth hooks и HttpOnly refresh bridge; публичный generic hooks transport для Auth заменяется typed façades по ADR-013, но миграция кода ещё не выполнена |
| [ADR-013](GUEST_TYPED_VFS_SURFACE_DECISION_RU.md) | Guest surface через typed VFS façades | Принято | В процессе | Реализованы typed `/api/v2/auth/*`, Public Site API, actor-filtered browser route resolution и `404` для guest на generic `/api/v2/vfs/*`; Auth временно использует Hook Runtime, а ACL evaluator и operation-resource grants отложены |

Допустимые статусы решения: `Предложено`, `Принято`, `Отклонено`, `Заменено`.

Допустимые статусы реализации: `Не реализовано`, `В процессе`, `Реализовано`,
`Частично устарело`. Статус реализации следует обновлять при изменении рабочего
кода, а не только целевой документации.
