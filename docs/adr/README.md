# Архитектурные решения

В этой папке находятся самостоятельные ADR проекта. Концепции, обзоры текущей
реализации и планы разработки остаются на уровень выше в `docs/`.

| ADR | Решение | Статус решения | Статус реализации | Примечание |
| --- | --- | --- | --- | --- |
| [ADR-003](ACL_LIFECYCLE_ARCHITECTURE_RU.md) | ACL lifecycle, durable journal, generation, tombstone и overlay | Принято | Не реализовано | В VFSv2 есть только синхронная точка расширения `ResourceLifecycleSink`; journal, generation, tombstone, overlay и recovery отсутствуют |
| [ADR-004](VFS_V2_SHARED_PROVIDER_DECISION_RU.md) | Shared Provider как заменяемая проекция канонических VFS URI | Принято | В процессе | Реализован ACL-free каркас: модель ссылки, собственное SQLite-хранилище без связи с `users`, CRUD записей, `incoming/outgoing`, делегирование через `BoundVFS` и provider-owned migration group; системный database registry не знает Shared, provider не включён в основную pre-prod сборку, `Control` намеренно возвращает unsupported, не реализованы `acl_grant_uri`, ACL и lifecycle |
| [ADR-005](VFS_V2_SCOPE_RESOLUTION_DECISION_RU.md) | Разделение разрешения scope и авторизации входа в него | Принято | В процессе | Explicit/default lookup разделены, а VFS Core проверяет synthetic scope gate; текущий owner bridge покрывает только вход и в demo-композициях делегирует resource actions разрешающему authorizer. Безопасная owner-only production policy зафиксирована ADR-009, но ещё не реализована; ACL cross-scope сценарии отсутствуют |
| [ADR-006](ACL_SPARSE_NAMESPACE_TREE_PROPOSAL_RU.md) | Разреженное дерево ACL namespace с отдельными roots и внутренними node ID | Предложено | Не реализовано | Альтернатива части ADR-003: rename/move меняет один узел вместо prefix overlay и массовой материализации; до принятия ADR-003 остаётся действующим решением |
| [ADR-007](VFS_V2_HTML_PROVIDER_DECISION_RU.md) | HTML Provider как метадоменная проекция физических файлов сайта | Предложено | В процессе | Реализованы Store schema v4 с миграциями bundle/visibility/templates, доменное ядро страниц, typed VFS-проекция, обязательная visibility текущих Site/Publisher/Page, безопасный page bundle binding и demo `cmd/vfsv2html`; editor slice предоставляет actor-filtered `editor/model.xml` и optimistic `editor/layout.xml`; template slice предоставляет атомарную immutable-установку, content-addressed blobs, manifest allowlist и read-only `/templates/<key>/<version>`; reviewed builder собирает `default-spa/7` и устанавливает его через VFS в demo bootstrap; HTML Provider SDK module объявляет `get-static` и `get-page`; site adapter передаёт typed `site_uri` и `template_key`, а hooks читают целевые ресурсы через actor-bound VFS; active publication, Block/Theme/Publication consumers, поиск/sitemap, production-регистрация, реальный ACL и lifecycle ещё отсутствуют; актуален [практический план](../VFS_V2_HTML_PROVIDER_IMPLEMENTATION_PLAN_RU.md) |
| [ADR-008](VFS_V2_SERVER_HOOKS_DECISION_RU.md) | Серверные hooks как versioned orchestration-сценарии над actor-bound VFS | Предложено | В процессе | Реализованы transport-neutral typed SDK, immutable versioned definitions, trusted native engine, provider-module registration и actor-bound Runtime с limits/structured errors и in-memory idempotency результатов. Hook не прикреплён к resource URI: сценарий получает typed input и выполняет нужные VFS-вызовы тем же actor; HTTP adapter реализует `POST /api/v2/vfs/hooks/{hook-key}/run` только для прямого запуска. Ещё отсутствуют durable execution/step journal, resume/compensation, sandboxed engine, hook policy и observability |
| [ADR-009](PREPROD_SERVER_RUNTIME_DECISION_RU.md) | Единственная pre-prod сборка `cmd/server`, границы runtime и pre-ACL policy | Принято | В процессе | `cmd/server` использует `internal/serverapp` и `.env`/environment config; подключены health, VFS HTTP, Auth hooks и Site HTTP для отдельного `SITE_URI` scope; public-site pre-ACL bridge временно заменяет будущие ACL grants |
| [ADR-010](SQLITE_MIGRATIONS_DECISION_RU.md) | Централизованные ordered/transactional SQLite migrations по группам владельцев | Принято | Реализовано | Общий runner и version table; database registry содержит только core/Auth/VFS, а composition root передаёт выбранные Local/HTML groups; Shared остаётся полностью provider-owned; настроены SQLite open и отдельная `cmd/migrate`, legacy Auth stores сохранены до следующей итерации |
| [ADR-011](AUTH_SESSION_JWT_LIFECYCLE_DECISION_RU.md) | Session-backed JWT lifecycle, разделение access/refresh и fail-closed rotation | Принято | Реализовано | Auth получает secret/issuer/audience/TTL через dependency; runtime использует hashed refresh в `sessions`, CAS rotation и reuse revoke; блокировка, password change и logout отзывают sessions; legacy stores сохранены, но не участвуют в runtime |
| [ADR-012](USERS_PROVIDER_AUTH_HOOKS_DECISION_RU.md) | Guest actor, Users Provider и Auth-owned hooks через единый VFS transport | Принято | Реализовано | Реализованы session-scoped guest actor, общий scope `system`, Users profile store/provider, Auth hooks и HttpOnly refresh bridge; `auth.register` через VFS создаёт только personal default scope пользователя; connections и прочий provisioning отсутствуют |

Допустимые статусы решения: `Предложено`, `Принято`, `Отклонено`, `Заменено`.

Допустимые статусы реализации: `Не реализовано`, `В процессе`, `Реализовано`,
`Частично устарело`. Статус реализации следует обновлять при изменении рабочего
кода, а не только целевой документации.
